# OWCS Stats · Umami 运营分析与埋点维护

本次口径版本为 **2**。事件名称和字段在 Umami 内直接显示中文，赛事、对阵、选手、战队、英雄和地图优先显示名称，ID 留作追溯。完整清单见 [事件字典](analytics-events.md)。历史事件不改写，发布前后的数据不能直接拼接为同一口径。

## 先看什么

| 运营问题 | 在 Umami 查看 | 判断方式与限制 |
| --- | --- | --- |
| 流量来自哪里，活动是否有效 | 原生浏览量、访客、来源、设备、UTM | URL 只保留公开页面路径；首次访问保留合法的 utm_source / utm_medium / utm_campaign。来源外站只保留域名。 |
| 哪些赛事、战队、选手值得持续运营 | `访问-内容加载完成`，按「页面」「赛事」「比赛」「战队」「选手」展开 | 过滤「结果=成功」；加载完成包含主动换赛事，不等同于 PV。对阵用双方名称，重赛用赛事、比赛日期、比赛ID区分。 |
| 首页入口是否有效 | `导航-打开比赛/赛前分析/战队/选手` 的「入口」 | 结合同一功能曝光与详情加载结果，查看入口发现、点击和成功到达。详情直达没有导航点击，是正常情况。 |
| 功能没看到，还是看到后不使用 | `功能-有效曝光` 的「功能」；相应筛选、展开、排序、对比事件 | 曝光要求进入视口并连续可见 1 秒；同一内容访问/赛事/功能去重。使用可能发生在 1 秒前，不能把全部操作次数直接除以曝光次数当作严格转化率。 |
| 用户真正关心哪些指标 | `分析-调整排序`、`分析-展开明细` 的「指标」 | 只统计明确用户操作；默认选择和自动回退不表示偏好。 |
| 对比是否有用 | `分析-选择对比` 的「功能」「对比选手」「已选人数」 | 已选人数至少 2 才表示完整对比；选择、改选、清除是不同操作次数。 |
| 时间线是否值得继续投入 | 比赛时间线曝光、切换回合、筛选事件、查看事件 | 筛选「结果=成功」的曝光作为可用功能范围。拖动、滚轮、悬停、自动渲染不逐次上报。 |
| 投票是否顺畅 | `投票-提交支持` → `投票-提交结果` | 结果成功才是接口确认；「首次支持/更改支持/重复支持」分别分析。Umami 不是票数数据库。 |
| 导出是否真正可用 | `导出-开始生成` → `导出-生成结果` | 成功口径是「预览已生成」。浏览器不能确认用户是否长按保存，更不能当分享成功。 |
| 助手是否被使用且完成回答 | 助手曝光 → 打开 → 发送问题 → 回答结果 | 分析预设/自主提问、结合页面、完成/失败/停止/中断、首字与总耗时；不把完成回答视为答案正确或用户满意。 |
| 页面质量是否阻碍使用 | `访问-内容加载完成` 的结果、耗时；`质量-接口失败` 的资源、HTTP状态 | 耗时是业务加载时间，不是 Web Vitals；同类同状态接口失败 10 秒去重，不能当精确请求失败率。 |

## Umami 操作方式

1. 进入当前网站，选**发布后的时间段**。原生 Pages 表现在按 5 类公开页面聚合，不再被含数据库 ID、图片地址和标签状态的长 URL 分散。
2. 在 Events / Event data 中选择中文事件，再展开「赛事」「比赛」「功能」「入口」等字段。用「口径版本=2」隔离新口径。浏览量看原生页面统计，业务实体兴趣看加载完成和导航事件。
3. 有 Reports 权限的账户可创建漏斗：功能曝光 → 相关操作 → 结果，按页面/赛事/功能限定同一范围。优先比较访客或会话转化；用户可能反复操作，事件次数比不是用户转化率。不同功能不要混算总曝光。
4. 共享看板只展示其权限允许的内容。高级报告需要登录；本次前端改造不会自动在 Umami 后台创建报告或修改历史数据库。
5. 每周先看来源与赛事兴趣，再看关键功能使用、失败/空数据、加载耗时。样本量小的细分保留原数，不从少量点击推断需求强弱。

建议固定 4 组报告：**流量与赛事兴趣、内容导航、分析功能使用、操作结果与质量**。新口径上线后先积累完整的比赛周期，再与下一个可比比赛周期比较。

## 覆盖与发送规则

- 5 个公开页面：赛事首页、比赛详情、赛前分析、战队详情、选手详情。首页赛程/积分/赛事数据分类、日期筛选、战队与选手排行、对比、地图/英雄展开、详情分区、时间线、回放复制、投票、图片导出、赛事助手均有相应行为事件。
- 页面 PV 由 Vue Router 统一负责，Umami 自动采集关闭。同一实体内切换 tab、筛选或 `router.replace` 不新增 PV；切到另一个实体新增 PV。页面加载与业务操作为独立事件。
- 开发服务器和 localhost 默认不加载 Umami；管理页不记录 PV/事件。静态展示包和 API 展示包延续既有不启用 Umami 的边界。
- 用户 `localStorage['umami.disabled']` 开关受尊重。埋点不创建用户 ID、投票身份、持久化队列或对话标识。
- SDK 加载前最多缓存 100 条，60 秒过期；每条固定页面、标题、来源和数据。失败不阻断产品、不无限重试；网络阻断和关闭页面仍可能丢失事件，不能宣称零丢失。
- 异步导出、投票、助手和 API 失败固定发起时的上下文，避免用户导航后串页。公开页异步错误不记录后台 URL、错误原文、请求体或凭据。
- 事件字段使用白名单，只支持有限长度字符串、有限数值和布尔值；缺失值省略，不以 0 代替。多选名称最多展示 8 项，已选人数保留完整数量。名称解析失败明确显示「名称未解析」，此值可作为埋点质量检查项。
- 问题/回答正文、自由文本、会话 ID、token、录像代码、剪贴板内容、图片 URL、任意查询参数不进入 Umami。姓名字段来自公开选手资料。

## 本地调试与验收

```powershell
$env:VITE_ANALYTICS_DEBUG='true'
npm run dev
```

浏览器控制台查看 `window.__OWCS_ANALYTICS__.records`。调试记录最多 200 条，使用同一字段清洗规则；默认不发正式数据。结束后移除当前 shell 的环境变量。

```powershell
npm run test:analytics
npm run verify:analytics
npm run build
```

浏览器验收使用独立本地生产构建预览、合成赛事/API/助手响应和拦截的统计接收端，覆盖真实 Vue 操作，不发真实投票、模型或生产统计请求。结果保存在 `.local/analytics/`。如需验证当前线上 SDK 兼容性，可将**已下载的公开 script.js**绝对路径通过 `UMAMI_TRACKER_FIXTURE` 传入，全部接收请求依然被本地拦截。测试数据不是上线运营效果。

配置优先级：环境变量 `VITE_UMAMI_SCRIPT_URL`、`VITE_UMAMI_WEBSITE_ID` 优先于 `src/config/analytics.js`。`VITE_ANALYTICS_ENABLED=false` 为构建级关闭；只有使用隔离测试网站时才显式设置 `true`。不要把本地点击发到正式 Website ID。

发布后验收：新时间窗口内查看 5 类 PV；抽查一场对阵、一名选手和一次成功/失败结果；确认名称与页面一致；确认后台访问不增长；检查「名称未解析」占比。旧事件保留，不补造历史名称。部署/线上接收与后台报告配置需独立验证，不能用本地拦截测试替代。

## 新增或修改埋点

1. 先写清运营问题、触发动作、成功定义和适用分母，再在 `src/analytics/catalog.mjs` 注册稳定代码键、中文名称、字段和业务说明。不要在事件名拼接实体名、日期或 ID。
2. 新字段须在 `FIELDS` 注册显示名称并放入事件白名单；受控枚举放入 `LABELS`。公共实体优先传已有数据中的名称和 ID；不要为埋点新增 API 请求。
3. 页面末尾 `useAnalyticsContext(() => ({ seasonId, ... }))` 注册当前实体。组件使用 `useFeatureAnalytics('功能名称', getter)`；在用户处理函数触发 `track('filter_change', data)`，不要通过监听初始化中的 ref 代替用户动作。
4. 网络操作开始前 `captureAnalyticsContext()`，开始与终态使用同一快照。成功事件必须在确认结果后发送。对默认初始化、取消、失败、重复动作定义清楚语义。
5. 需要曝光分母时给真实可见容器绑定 `v-analytics-view`，加载中传 `null`，绑定值随赛事/地图/功能变化。不要对每行、每秒、滚轮或 hover 上报。
6. 运行 `npm run docs:analytics` 更新生成的事件字典，增加有意义的测试并运行验收。单元测试会拒绝未知事件键和分散的 SDK 调用；发布工作流已加入埋点测试。
7. 删除或改变业务含义时记录迁移日期，必要时升级口径版本。不要悄悄复用同名事件表达新行为。

底层契约参考：[Umami tracker functions](https://umami.is/docs/tracker-functions)、[tracker configuration](https://umami.is/docs/tracker-configuration)、[event data](https://umami.is/docs/event-data)。本次同时静态核对了站点当前公开 SDK 的 `data-auto-track` 和 `track(callback)` 实现。
